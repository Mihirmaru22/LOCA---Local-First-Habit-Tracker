# Phase R · R6 — Onboarding & First‑Run Experience (In Depth)

> **Mission:** turn the Day‑1 → Day‑7 → Day‑30 → Month‑6 → Year‑2 value curve (R1) into a concrete first‑run design. Answer: **what does LOCA ask, what does it infer, what does it postpone, and what value does it deliver in the first session?**
>
> **Format:** every book and topic ends with the standard five blocks — **Lessons for LOCA · Anti‑patterns · Design implications · Open research questions · Ideas to experiment with** — tied to D1–D4.
>
> **The thesis R6 argues:** onboarding is not a tour — it is the **fastest honest path to first value** plus the **seeding of the user's intent.** LOCA's Life value is inherently slow (inference needs days; patterns need weeks), so the onboarding job is *not* to fake early value but to (a) deliver an **honest Day‑1 win** from the one thing that works instantly (the habit record + a first reflection), (b) **seed a question/direction** that gives the whole engine a purpose, and (c) **postpone every permission to the moment it visibly pays off.** LOCA's current onboarding does none of these.

> **LOCA's current onboarding, diagnosed (from the code):** a 4‑card conceptual `LifeOnboardingSheet` that *explains* Life, **asks nothing, infers nothing, seeds no goal**, and is decoupled from the permission‑framing sheets (`ContextPermissionView`, `HealthKitPermissionView`) which fire on the Today tab without a named payoff. Net: the user reads three abstract cards, then lands on an empty Life tab. Zero activation. This is a first‑run instance of **D1**.

---

## Part A — The first‑run framework

Four concepts define good onboarding; each has a LOCA translation:

1. **Time‑to‑First‑Value (TTFV) / Time‑to‑Aha.** Minimize the time until the user *experiences* core value. LOCA's honest instant value is **logging a habit and getting a first reflective moment** — not the (slow, currently deflated) Life read.
2. **Activation.** The specific event that predicts retention. LOCA must *define* its activation event (candidate: "logged a habit **and** wrote/received one honest reflection **and** set an intent") and design the first run to reach it.
3. **Ask / Infer / Postpone.** Ask the *minimum* that seeds value (one intent question); infer nothing risky; postpone permissions and configuration to the moment of payoff.
4. **The value curve is the onboarding.** Because LOCA's value genuinely compounds over weeks, onboarding must **set honest expectations** ("this gets richer as you go") and deliver a real *small* win now — not overpromise a Day‑1 life model.

**The core design:** Day‑1 = *one question + one habit logged + one honest reflection + expectation set.* Everything else is postponed.

## Part B — Book notes

### 1. *Hooked* — Nir Eyal *(onboarding/trigger sections only, read critically)*
Onboarding's job in the Hook framework is to move the user from **external triggers** (the app prompts them) to **internal triggers** (an internal cue — boredom, curiosity, an emotion — pulls them back unprompted). The first cycles must deliver reward and secure a small **investment** that increases future value.
- **Lessons for LOCA:** the honest, non‑manipulative version: help the user form an **internal trigger for reflection** (e.g. "after I log, I reflect," or "when I wonder how my week went, I open LOCA") — and make the first investment (a logged habit, a first reflection, a stated intent) genuinely increase the record's value *to the user*. Use trigger insight to build a healthy habit, not compulsion.
- **Anti‑patterns:** engineering compulsion in onboarding (variable‑reward hooks, guilt triggers); investment that locks in rather than serves (R3).
- **Design implications:** onboarding seeds a reflection habit tied to an existing cue (logging); first investment = the user's own growing record.
- **Open research questions:** what internal trigger can LOCA honestly cultivate for reflection?
- **Ideas to experiment with:** an onboarding that explicitly stacks reflection onto the first habit log (R3 habit‑stacking).

### 2. *Continuous Discovery Habits* — Teresa Torres
Activation is a **learning problem**: you discover what activates users by talking to them **continuously** (weekly touchpoints), mapping opportunities to outcomes (opportunity‑solution trees), and testing assumptions — not by guessing the perfect flow.
- **Lessons for LOCA:** don't *guess* LOCA's activation event — **discover it** by testing onboarding variants with real users weekly (pairs with Krug's cheap testing, R5). Treat the first‑run design as a set of falsifiable assumptions.
- **Anti‑patterns:** designing onboarding by intuition and shipping it once; no user contact; assuming the activation event.
- **Design implications:** instrument and test candidate activation events; iterate onboarding continuously.
- **Open research questions:** which candidate activation event actually predicts LOCA D7/D30 retention?
- **Ideas to experiment with:** weekly 3–5‑user onboarding tests, each falsifying one assumption.

### 3. *The Lean Product Playbook* — Dan Olsen
The **Product‑Market‑Fit Pyramid** (target user → underserved needs → value proposition → feature set → UX); define the **core value hypothesis** and validate it with an MVP; onboarding must deliver the *core* value, not the full feature set.
- **Lessons for LOCA:** name LOCA's **core value hypothesis** ("honest reflection on your real life makes people feel understood and self‑aware") and make onboarding deliver *that*, not a tour of 12 Life surfaces. If the core value isn't validated, no onboarding polish saves it.
- **Anti‑patterns:** onboarding the full feature set; polishing UX atop an unvalidated value prop.
- **Design implications:** onboarding = shortest path to the *core* value hypothesis; validate that first.
- **Open research questions:** is LOCA's core value hypothesis reflection (R2) — and is it validated?
- **Ideas to experiment with:** a stripped MVP onboarding that delivers only the core reflective value, tested for resonance.

### 4. *Lean Analytics* — Alistair Croll & Benjamin Yoskovitz
Metrics discipline: the **One Metric That Matters**, the **AARRR/pirate funnel** (Acquisition → **Activation** → Retention → Referral → Revenue), cohort analysis, and the principle that **activation is the pivotal early metric**. Measure the funnel; find where users drop.
- **Lessons for LOCA:** define an **activation metric** and an early **OMTM** (likely an activation or D7‑retention rate), instrument the onboarding funnel, and find the drop‑off. LOCA currently has no defined activation event — you can't improve what you don't measure.
- **Anti‑patterns:** vanity metrics (installs); no activation definition; unmeasured funnel.
- **Design implications:** define activation; instrument the first‑run funnel; watch cohorts.
- **Open research questions:** what activation definition best predicts LOCA retention?
- **Ideas to experiment with:** instrument a first‑run funnel (open → question set → habit logged → reflection → return D2).

### 5. *The First Minute* — Chris Fenning *(applied as an onboarding analogy — note: it's primarily a business‑communication book)*
Its real subject is structuring the **first minute of a conversation**: establish **context, intent, and key message** immediately so the listener isn't lost. *Transferred to onboarding:* the first minute must answer "what is this, why does it matter to me, and what do I do now" — fast, framed, and oriented.
- **Lessons for LOCA:** LOCA's first minute must instantly establish **what it is** (an honest mirror/record, not an oracle — the conceptual model, R5/Norman), **why it matters to you** (understand your own life), and **what to do now** (log + reflect). The current 3 abstract cards bury this.
- **Anti‑patterns:** abstract framing that delays context/intent; making the user infer the point.
- **Design implications:** a first‑minute that states model + value + first action, concretely.
- **Open research questions:** can users state "what LOCA is" correctly after the first minute?
- **Ideas to experiment with:** a one‑screen "what this is / why it matters / do this now" opener, comprehension‑tested.

## Part C — Research topics

### Group 1 — Value, activation, funnels

**T1. First‑Time User Experience (FTUE).** The first session disproportionately determines retention; it must deliver value and orientation, not setup.
- *Lessons for LOCA:* make session one deliver a real reflective win, not three explainer cards.
- *Anti‑patterns:* setup‑heavy/explainer‑only first session.
- *Design implications:* value‑first FTUE.
- *Open questions:* what's the minimum first session that activates?
- *Experiment:* value‑first vs explainer‑first FTUE.

**T2. User activation.** The event where a user first experiences core value; the strongest early retention predictor.
- *Lessons for LOCA:* **define** the activation event (candidate: log + first reflection + intent set) and engineer toward it.
- *Anti‑patterns:* no defined activation; hoping users "figure it out."
- *Design implications:* design the whole first run backward from the activation event.
- *Open questions:* which activation definition predicts D30 best?
- *Experiment:* test 2–3 candidate activation events against retention.

**T3. Time‑to‑First‑Value (TTFV).** Minimize time to first real value; every second before it leaks users.
- *Lessons for LOCA:* shortest honest path to value = log a habit + one reflection. Cut everything between open and that.
- *Anti‑patterns:* permission walls/explainers before first value.
- *Design implications:* compress TTFV ruthlessly.
- *Open questions:* what's LOCA's current TTFV, and its floor?
- *Experiment:* measure and halve TTFV.

**T4. Time‑to‑Aha.** The moment the user *gets it* — understands the value for them.
- *Lessons for LOCA:* LOCA's aha is likely "it reflected something true about *my* real day" — engineer a first such moment from the first log.
- *Anti‑patterns:* aha deferred to weeks out (current: real reflection needs data).
- *Design implications:* manufacture an honest first aha from Day‑1 data (even one habit).
- *Open questions:* what's the earliest honest aha LOCA can produce?
- *Experiment:* a Day‑1 reflection grounded in the single first log.

**T5. Product adoption funnels.** Acquisition→activation→retention; find and fix the biggest leak.
- *Lessons for LOCA:* instrument the funnel; the current biggest leak is almost certainly activation (empty Life after explainer).
- *Anti‑patterns:* unmeasured funnel; optimizing the wrong stage.
- *Design implications:* measure; fix the largest leak first.
- *Open questions:* where's LOCA's biggest first‑week leak?
- *Experiment:* funnel instrumentation + leak analysis.

**T6. User activation metrics.** Defining/measuring the activation event and rate.
- *Lessons for LOCA:* pick one activation metric as the onboarding OMTM (Lean Analytics).
- *Anti‑patterns:* vanity metrics.
- *Design implications:* single activation OMTM.
- *Open questions:* which metric?
- *Experiment:* instrument and baseline it.

**T7. User drop‑off during onboarding.** Where and why users quit the first flow.
- *Lessons for LOCA:* map drop‑off per onboarding step; likely spikes at explainer length and any early permission wall.
- *Anti‑patterns:* long flows; early asks.
- *Design implications:* shorten; remove early friction.
- *Open questions:* which step sheds the most users?
- *Experiment:* per‑step drop‑off analysis.

### Group 2 — Progressive onboarding & permissions

**T8. Progressive onboarding.** Teach over time at the moment of need, not all upfront.
- *Lessons for LOCA:* teach Life surfaces *when the user reaches them with data*, not in an upfront card stack.
- *Anti‑patterns:* front‑loaded explainer dump.
- *Design implications:* just‑in‑time teaching across sessions.
- *Open questions:* what must be taught Day‑1 vs later?
- *Experiment:* move all but essential teaching out of the first session.

**T9. Progressive permission requests.** Request each permission when its value is about to be delivered, not at launch.
- *Lessons for LOCA:* ask Calendar right before "see who you spend time with," HealthKit before body/energy signals, Notifications before the weekly ritual — never upfront.
- *Anti‑patterns:* upfront permission gauntlet; asking before showing value.
- *Design implications:* contextual, payoff‑anchored permission timing.
- *Open questions:* what's the ideal moment for each permission?
- *Experiment:* move each permission to its point‑of‑value.

**T10. Permission UX (HealthKit / Calendar / Location / Notifications).** iOS system prompts are **one‑shot** (deny is near‑permanent); **prime** with a pre‑permission screen that explains the payoff before the system dialog.
- *Lessons for LOCA:* LOCA *has* priming views (`ContextPermissionView`, `HealthKitPermissionView`) — **connect them to the moment of value and name the payoff**, and never trigger the one‑shot system prompt without priming. This directly fixes the People‑empty confusion (D2/F7): the user skips Calendar because they were never shown what it unlocks.
- *Anti‑patterns:* raw system prompts without priming; asking at launch; no payoff named; re‑asking after denial (can't — one‑shot).
- *Design implications:* prime → explain payoff → system prompt, all at the point of value; graceful degradation on deny.
- *Open questions:* which permission's payoff is most compelling to lead with?
- *Experiment:* primed‑at‑value vs current for Calendar grant rate.

**T11. Personal data collection trust during onboarding.** Asking for sensitive data before earning trust tanks conversion; explaining *why* and *where it stays* (on‑device) raises it.
- *Lessons for LOCA:* lead permission asks with LOCA's **local‑first/on‑device** promise (R4) — a real trust asset — and a concrete "why." Trust before data.
- *Anti‑patterns:* sensitive asks before trust; no "why"; no privacy assurance.
- *Design implications:* privacy‑first framing on every data ask.
- *Open questions:* does the on‑device promise measurably raise grant rates?
- *Experiment:* privacy‑framed vs neutral permission priming.

### Group 3 — Education, discovery, overload

**T12. Empty‑state onboarding.** Use empty states to teach what will appear and how. **(LOCA strength — extend.)**
- *Lessons for LOCA:* keep the honest empty states as onboarding surfaces; they teach without a tour.
- *Anti‑patterns:* blank/broken empties; empties with no path.
- *Design implications:* every empty teaches + offers the next step.
- *Open questions:* can empties carry most of the "what's coming" teaching?
- *Experiment:* empties‑as‑onboarding vs card‑stack.

**T13. Just‑in‑time education.** Teach at the moment of need; micro, contextual.
- *Lessons for LOCA:* explain each Life surface the first time the user opens it *with data*, in one line.
- *Anti‑patterns:* upfront teaching of unseen features.
- *Design implications:* one‑line contextual tips at first meaningful encounter.
- *Open questions:* which tips actually get read/used?
- *Experiment:* JIT one‑liners vs upfront cards.

**T14. Feature discovery.** How users find features; discoverability without tours.
- *Lessons for LOCA:* make reflect/correct/drill/ask discoverable via visible affordances (R5 recognition), not a tour.
- *Anti‑patterns:* buried features (the pre‑fix micro‑check‑in); tour‑dependent discovery.
- *Design implications:* visible affordances; progressive reveal.
- *Open questions:* which key features are currently undiscoverable?
- *Experiment:* surface the top‑3 hidden features.

**T15. Habit‑forming onboarding.** Get the user to the core habit loop early (ethically, R3).
- *Lessons for LOCA:* form the **log→reflect** loop in the first session; anchor reflection to logging (habit stacking).
- *Anti‑patterns:* delaying the core loop; compulsion mechanics.
- *Design implications:* first‑session core‑loop formation, ethically.
- *Open questions:* does first‑session loop completion predict retention?
- *Experiment:* onboarding that completes one log→reflect loop.

**T16. Product tours vs guided learning.** Coach‑mark tours are widely **ignored/skipped**; learning‑by‑doing sticks.
- *Lessons for LOCA:* **avoid a tour**; teach by doing (log a real habit, get a real reflection).
- *Anti‑patterns:* multi‑step coach‑mark tours.
- *Design implications:* learn‑by‑doing over tours.
- *Open questions:* does any tour beat learn‑by‑doing for LOCA?
- *Experiment:* tour vs do‑it‑now, retention compared.

**T17. Interactive onboarding.** Do, don't watch; action beats explanation.
- *Lessons for LOCA:* first session = *do* one real thing (log + reflect), not read cards.
- *Anti‑patterns:* passive explainer onboarding (current).
- *Design implications:* action‑first onboarding.
- *Open questions:* which first action activates best?
- *Experiment:* action‑first vs explainer‑first.

**T18. Cognitive overload during onboarding.** Too much too soon → abandonment (R3/R5 cognitive load).
- *Lessons for LOCA:* ask one thing, teach one thing, do one thing. The current 3 cards + decoupled permission sheets already risk overload.
- *Anti‑patterns:* multi‑ask, multi‑teach first runs.
- *Design implications:* radical minimalism in the first session.
- *Open questions:* what's the minimum viable first run?
- *Experiment:* strip the first run to a single ask + action.

### Group 4 — Abandonment & exemplars

**T19. Why users uninstall apps within the first week.** No perceived value, friction, confusion, permission distrust, and unmet expectations dominate first‑week churn.
- *Lessons for LOCA:* LOCA is exposed on **no Day‑1 value** (empty Life) and **permission distrust** (upfront, un‑primed). Deliver an honest small win and defer/priming permissions.
- *Anti‑patterns:* empty first value; un‑primed permission asks; overpromising.
- *Design implications:* Day‑1 win; primed permissions; honest expectations.
- *Open questions:* what's LOCA's first‑week uninstall driver?
- *Experiment:* first‑week cohort exit survey.

**T20. Why users abandon onboarding.** Too long, too much asked, unclear value, forced account/permissions.
- *Lessons for LOCA:* shorten; ask one thing; make value clear; defer account/permissions.
- *Anti‑patterns:* long flows; early gates.
- *Design implications:* one‑ask, value‑clear, gate‑free onboarding.
- *Open questions:* which factor drives LOCA onboarding abandonment?
- *Experiment:* onboarding‑length A/B.

**T21. Best onboarding patterns — Apple, Duolingo, Notion, Day One, Daylio, Headspace, Stoic, Reflectly.**
- **Apple:** minimal, respectful, **permissions deferred to point of use**; strong conceptual clarity. → borrow deferral + clarity.
- **Duolingo:** **goal question first** ("why are you learning?"), **value before signup** (a lesson before account), streak seeded. → borrow goal‑first + value‑before‑commitment.
- **Notion:** template/learn‑by‑doing, but **blank‑canvas overload** is its onboarding weakness. → borrow learn‑by‑doing, avoid blank‑canvas overwhelm.
- **Day One:** minimal but **blank‑page** friction. → borrow minimalism, avoid blank page (seed the first entry).
- **Daylio:** **first entry in seconds** — radical low friction. → borrow friction‑zero first action.
- **Headspace:** **goal question + immediate first meditation** (do‑it‑now value). → borrow goal + immediate first practice.
- **Stoic / Reflectly:** **prompt‑led first experience** (a first reflection immediately). → borrow prompt‑led first reflection.
- *Lessons for LOCA:* synthesize — **Duolingo/Headspace goal‑question + Daylio friction + Stoic/Reflectly prompt‑led first reflection + Apple permission deferral**, over LOCA's real habit log. This *is* the LOCA onboarding.
- *Anti‑patterns:* Notion blank‑canvas overload; Day One blank‑page; upfront permissions.
- *Design implications:* goal question → instant low‑friction action → seeded first reflection → deferred permissions.
- *Open questions:* which exemplar's activation model fits LOCA's slow‑value reality best (Headspace's "do it now" seems closest)?
- *Experiment:* a Duolingo‑style goal‑first + Headspace‑style do‑it‑now LOCA onboarding.

## Part D — R6 synthesis: the LOCA first‑run design

### The proposed first run (concrete, honest, D1‑fixing)
1. **First minute — orient (Fenning):** one screen — *"LOCA is a private mirror for your real life. It reflects what you actually do; you make the meaning. Let's start."* (states model + value + action).
2. **Ask one thing (Duolingo/Headspace, QS R3):** *"What do you want to understand about yourself?"* → seeds **Direction/Ask** and gives the engine intent. Skippable, one tap.
3. **Do one real thing (Daylio friction, interactive onboarding):** log the first habit (or pick one), in seconds.
4. **Seed the first reflection (Stoic/Reflectly, Apple Journal R1):** an honest, tiny reflection grounded in that first log — the first *aha* from real data.
5. **Set honest expectations (Oura, R1):** *"Your read gets richer over the next days as you log."* — no overpromise.
6. **Postpone permissions (Apple, T9/T10):** no permission asked yet; each is primed at its point of value later (Calendar → People, Health → energy, Notifications → weekly ritual).
7. **Activation event reached:** intent set + habit logged + one reflection + expectation set.

Everything else — the 12 Life surfaces, chapters, patterns — is taught **just‑in‑time**, when the user reaches it with data.

### The value curve as designed onboarding
| Horizon | Honest promise | Delivered by |
|---|---|---|
| **Day 1** | "I set an intent, logged, and got one true reflection." | steps 1–5 above |
| **Day 7** | "My daily read is starting to say something real." | fixed inference (no F1) + accumulating data |
| **Day 30** | "First honest patterns and a forming chapter." | patterns/events with confidence (R4) |
| **Month 6** | "A record I revisit; nostalgia + meaning." | compounding record (R2‑T9) |
| **Year 2** | "My life, honestly recorded — an autobiography." | the moat (R1/R2) |

### Recurring onboarding principles
- **Fastest honest path to first value** (TTFV/aha) — cut everything else.
- **Ask one thing that seeds intent** (goal‑first); infer nothing risky.
- **Do, don't tour** (interactive; learn‑by‑doing).
- **Postpone permissions to primed points of value** (never upfront; one‑shot prompts demand priming).
- **Trust before data** (privacy‑first framing; on‑device promise).
- **Set honest expectations** (LOCA's value is slow — say so, deliver a small real win now).
- **Teach just‑in‑time**; let empty states carry "what's coming."
- **Measure activation**; discover it, don't guess (Torres + Lean Analytics).

### Anti‑patterns (onboarding, additive)
- Explainer‑card stack with no action, no ask, no value (LOCA today).
- Upfront/un‑primed permission gauntlet (kills grant rate + trust — F7 root).
- Blank‑page / blank‑canvas first action (Day One/Notion trap).
- Overpromising a Day‑1 life model the data can't support (F1).
- Tours/coach‑marks as the teaching method.
- Sensitive data asks before trust is earned.
- Long, multi‑ask, gated first flows.
- No defined/measured activation event.

### Design implications for LOCA V3 (onboarding program)
1. **Replace the 4‑card explainer** with the 7‑step action‑first first run above. *(D1)*
2. **Add the Day‑1 intent question** seeding Direction/Ask. *(D1)*
3. **Deliver a seeded first reflection** from the first log (the honest Day‑1 aha). *(D1)*
4. **Re‑anchor every permission** to its point‑of‑value with priming + payoff + privacy framing. *(D2/F7)*
5. **Set honest expectations** about the slow value curve. *(anti‑F1 overpromise)*
6. **Define and instrument an activation metric**; test onboarding variants continuously. *(Lean Analytics/Torres)*
7. **Teach just‑in‑time**; keep/extend empty‑state teaching. *(R5 strength)*

### How R6 changes LOCA's direction
R1–R5 defined *what LOCA is and how it looks*; **R6 makes the first five minutes deliver it honestly.** The key insight: LOCA's value is genuinely slow, so onboarding must *not* fake a Day‑1 life model (that's the F1 overpromise) — it must deliver the **one honest instant win** (log → seeded reflection), **seed the user's intent**, **postpone every permission to a primed point of value**, and **set truthful expectations** about the compounding curve. The current explainer‑only sheet is the first‑run face of D1; the fix is action‑first, goal‑seeded, permission‑deferred, honestly‑paced.
